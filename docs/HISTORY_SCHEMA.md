# Private conversation history schema

H01 defines the Room database contract for the later persistence and history UI work. It stores conversation and message text, optional speech transcripts, structured tool outcomes, and optional per-conversation compact summaries in the app's private database directory. The schema does not store media paths or model prompts. A compact summary is a user-requested prompt aid stored on the conversation row; it is not automatic long-term memory and it is not sent off-device ([ADR 0019](adr/0019-explicit-conversation-compact.md)).

The HistoryDatabase is version 6 and exports its schema under app/schemas. Version 1 is a development schema baseline created before tool outcomes were added; it is not a schema shipped to existing users. Migration 1→2 adds tool outcomes with a foreign key to their parent message and a unique request ID. Migration 2→3 adds turn IDs and terminal status for idempotent completed-turn persistence. Migration 3→4 adds an optional speech-transcript status to distinguish a missing transcript from an unavailable local ASR result. Migration 4→5 adds an optional `mediaRef` for durable photo attachment paths so a user turn can be persisted before inference and recovered after process death ([ADR 0003](adr/0003-turn-write-ahead.md)). The reference is stored only after a complete private copy. A partial or truncated copy is discarded and does not replace an existing file. Migration 5→6 adds optional `conversations.summary` and `conversations.summarizedMessageCount` so an explicit compact can be persisted and restored when the conversation reopens ([#221](https://github.com/NotCherry/LFM3Pocket/pull/221)). Turn status also uses `GENERATING` / `INTERRUPTED` for in-flight recovery. Older rows keep a null status and their original transcript text.

Messages are ordered by a per-conversation sequence number protected by a unique index. Conversation ordering is deterministic for equal timestamps. Tool outcomes cascade with their message, and conversation deletion cascades through both tables. Inserts use Room's abort behavior so duplicate IDs, duplicate message positions, replayed request IDs, and orphan rows fail visibly instead of replacing history.

H01 supplies the schema, DAO, private database builder, migrations, and emulator coverage. H02 owns atomic conversation persistence; H03–H05 own history navigation, deletion, and end-to-end privacy behavior. V03 stores an actual ASR pass separately from the assistant response and shows an explicit unavailable state when it fails. Polish recognition accuracy and ARM64 qualification remain incomplete. No production database fallback or destructive migration is configured.

# Voice capture lifecycle

Voice input starts only after a foreground user tap and microphone permission. The controller checks permission before opening/starting and during capture; Android AudioRecord remains confined to a dedicated worker. Non-blocking PCM16 mono reads at 16 kHz allow Stop/cancel without waiting for further microphone samples. UI states are IDLE, STARTING, RECORDING, STOPPING and ERROR. Backgrounding cancels capture; Activity destruction closes the controller and suppresses stale completion. Returning never restarts capture automatically.

A recording is bounded to 60 seconds and requires at least 250 ms of samples. PCM is streamed to a unique private cache partial file, finalized with a WAV header and atomically renamed only after successful capture and release. Short input, revoked permission, initialization/read failure and cancellation delete the partial; startup discards leftovers after process death. A valid WAV attaches to the pending turn. This does not implement ASR, speech generation or transcript persistence.

RecordingControllerTest verifies no open before trigger, close-before-queued-start, denial/revocation cleanup, short-input retry and exact PCM/WAV shape. RecordingE2eTest drives actual UI with injected permission and PCM to avoid recording user/emulator audio or changing global permission state. ChatUiE2eTest separately drives Android's real permission denial UI and verifies text chat still works. Real microphone quality and Omni audio interpretation require physical-device evidence.
